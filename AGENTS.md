# tquilla-api: panduan project

- **Server tidak boleh percaya klien.** Validasi panjang/format input di server, normalisasi ulang URL di server, rate limit per IP (`CF-Connecting-IP`), batas ukuran body. Konstanta batas ada di `api-types::limits`, tetapi server memeriksa ulang.
- **Tidak ada unggah gambar.** R2 butuh kartu, jadi dibatalkan: avatar dibuat klien dari username, kontrak tidak punya `avatar_url`/`attachment_url`. Jangan menambah kolom gambar atau menyimpan base64 di database.
- **Tanpa kredensial di repo.** Rahasia lewat `wrangler secret` / `.dev.vars` (di-.gitignore). `Debug` untuk config/klien tidak boleh mencetak token (ada test-nya).
- **Pesan error ke klien umum saja.** Detail masuk `worker::console_error!`, bukan ke respons.
- **Endpoint admin**: hanya lewat `admin::authorized` (`ADMIN_TOKEN`, secret, min. 32 karakter, perbandingan waktu-konstan, gagal tertutup). Jangan menambahkan `Authorization` atau `DELETE` ke CORS: dashboard (`web/admin/`) dilayani Worker yang sama (satu origin), jadi tidak butuh CORS, dan situs lain tidak boleh bisa memanggil admin (ada tes). Semua handler admin lewat `routes::admin_gate` (token, lalu `panel::check_access`: 10 kegagalan per 15 menit per IP mengunci, juga untuk token benar); aksi yang berhasil dicatat dengan `audit(...)`. Tidak ada auto-hide dari laporan.
- **Semua kode di `crates/api` harus compile ke wasm32**: tanpa tokio, tanpa thread, tanpa crate native (`sqlx`, `libsql`, `rusqlite`, ...). Akses DB lewat `turso-http`.
- **Logika murni di luar `fetch`** supaya bisa dites native (`config`, `cors`, `health::ping` dengan transport palsu, router lewat `tower::oneshot`). Handler yang menyentuh `fetch` JS tidak bisa jalan di host.
- **`api-types` hanya boleh bergantung pada `serde`** (dipakai frontend di wasm32). Menambah endpoint = tambah konstanta di `paths` dan di `paths::ALL`. Validator URL bersama (`api_types::validate`) dipakai server dan frontend; jangan menduplikasinya. Endpoint konten: SQL di `crates/api/src/queries/*.sql` (juga diuji di `scripts/migrations.test.mjs`), logika generik atas `Transport` di `content.rs`, handler tipis di `routes.rs`. Guestbook: `chat.rs` (siap-kirim `prepare`, `check_rate`, `submit`, `report`, `reported`, `hide`, semuanya generik atas `Transport`); aturan teks (1–2000 karakter, 40 baris) ada di `api_types::chat` dan dipakai klien juga; IP tidak pernah disimpan, hanya hash dengan `RATE_LIMIT_SALT`. Pesan adalah Markdown (boleh berisi subset HTML, termasuk `<img>`) yang disimpan **apa adanya**; server tidak merender, tidak memeriksa gambar, dan tidak memproksinya. Path `/messages` dan tabel `chat_messages` tidak diganti nama (kompatibilitas mundur dengan Worker lama).
- **Fixture protokol** (`crates/turso-http/tests/fixtures/req_*.json`) dihasilkan encoder referensi lewat `scripts/gen_golden.mjs`; jangan diedit tangan. `resp_*.json` ditulis tangan dan divalidasi decoder referensi.
- Versi Rust dikunci di `rust-toolchain.toml`; saat menaikkannya, ubah juga `dtolnay/rust-toolchain@<versi>` di `.github/workflows/ci.yml` dan samakan dengan repo frontend.
- **Skema = file di `migrations/`** (lihat `migrations/README.md`). Jangan mengubah migrasi yang sudah dijalankan (checksum dicek runner); buat nomor baru. Tanpa `BEGIN`/`COMMIT` di dalam file. Setiap tabel baru dapat `CHECK` untuk URL (`http(s)://`, avatar/lampiran `https://` saja) dan panjang teks. `seeds/*.sql` dibangkitkan oleh `scripts/gen_seed.mjs`, jangan diedit tangan. Query selalu pakai `ORDER BY` eksplisit dan parameter (`?`), tidak pernah menyisipkan input ke string SQL.
- **`crates/migrate` native saja**, tidak boleh jadi dependensi `crates/api` (ureq dan TLS-nya tidak ada gunanya di Worker). Runner (`turso-http::migrate`) tetap murni dan dites dengan transport palsu.
- **Perintah yang harus hijau sebelum commit:**
  ```sh
  cargo fmt --all -- --check
  cargo clippy --workspace --all-targets --locked -- -D warnings
  cargo test --workspace --locked
  cargo clippy -p api --target wasm32-unknown-unknown --locked -- -D warnings
  node --test scripts/migrations.test.mjs
  node --test scripts/admin-ui.test.mjs
  node --test scripts/workflow.test.mjs
  ```
- **Jurnal (D5)**: `crates/api/src/journal.rs` (logika murni, dites native), `github.rs` (hanya `fetch`), kontrak di `api_types::journal`. Payload adalah **data, bukan tampilan**: jangan menambah field HTML/markup atau kalimat berbahasa tertentu. Nama repo/akun dari tabel `journal_*` masuk ke GraphQL **hanya sebagai variabel**, jangan pernah disisipkan ke teks query. Pengaturan jurnal yang bisa diedit admin ada di migrasi, bukan seed. Token GitHub hanya di header `Authorization` (tidak di body, log, atau `Debug`). Waktu: `time.rs`, bukan crate tanggal (wasm kecil).
- **Dashboard admin (D6)**: UI di `web/admin/` adalah JavaScript biasa **tanpa build step dan tanpa npm di CI**. Aturan (dites di `scripts/admin-ui.test.mjs`): tidak ada `innerHTML`/`eval`/inline script atau style/penyimpanan browser; token hanya di memori (`api.js`), tidak pernah di URL; CSP di `web/_headers` tidak boleh dilonggarkan (`script-src 'self'`); pustaka (htm+Preact) disalin ke `web/admin/vendor/` dan hash-nya dicek, jangan memuat dari CDN. Teks tampilan bahasa Indonesia biasa, bukan `Strings` frontend. Logika murni di `logic.js` (dites), jaringan di `api.js` (fetch disuntikkan untuk tes), tampilan di `app.js`. Tidak ada fitur "tambah kolom": skema berubah **hanya** lewat `migrations/`. Endpoint admin baru = konstanta di `api_types::paths` (+ `ALL`), `PATHS` di `api.js` (ada tes yang mencocokkan), handler dengan `gate!`, dan `audit` untuk aksi yang mengubah data. Modul `testing.rs` (`cfg(test)`) berisi transport palsu bersama. **Editor tabel (D6c)**: tabel yang boleh dikelola hanya yang ada di `TABLES` (`tables.rs`); nama tabel/kolom di SQL **hanya** dari daftar itu, nilai selalu di-*bind*, jangan menambah SQL mentah atau menerima nama kolom dari klien. SQL hasil daftar dikunci di `crates/api/tests-data/tables_sql.json` (dites di Rust dan dijalankan di SQLite oleh `scripts/migrations.test.mjs`); setelah mengubah daftar, regenerasi dengan `UPDATE_GOLDEN=1 cargo test -p api tables` dan **baca selisihnya**. Tabel baru = baris di `TABLES` + (bila perlu) migrasi; tabel sistem tetap `editable: false`. **Seed konten berlaku sekali** (`_seeded`, dibangkitkan `scripts/gen_seed.mjs`): jangan menulis seed yang menghidupkan lagi konten yang sudah dihapus lewat dashboard. Editor admin (`journal_admin.rs`, `moderation.rs`): masukan diperiksa ulang di server dengan pesan tetap (`PanelError::{Invalid,NotFound,Conflict}`), batas jumlah ditegakkan di SQL, `id` di path hanya bilangan bulat positif (`withId` di `api.js`, `parse_id` di server), isi entri tidak pernah dirender sebagai markup atau tautan, dan tiap aksi yang berhasil memanggil `audit` (tambahkan labelnya di `ACTION_LABELS`; ada tes yang memeriksa semua aksi punya label).
- **Pemeriksa radio (D7)**: `crates/api/src/radio_check.rs` (logika murni generik atas `Transport` dan `Probe`, dites native) dan `radio_probe.rs` (hanya `fetch`, seperti `github.rs`). URL stream memuat token: **jangan** ditulis ke log, pesan error, atau respons selain bagi admin; `ProbeError` sengaja tanpa teks. Yang boleh diketuk hanya yang lolos `radio_check::probeable` (https, host DNS biasa, port 443); jangan melonggarkannya, dan jangan mengikuti redirect lewat `fetch` (`redirect: manual`, tiap lompatan diperiksa ulang). Stasiun tidak dimatikan oleh satu kegagalan: ambang dan jeda ada di konstanta `FAIL_THRESHOLD` / `MIN_FAIL_SPAN_SECS`, dan ada tesnya. Anggaran subrequest plan gratis (50 per eksekusi, termasuk Turso) dijaga oleh `const` assertion; kalau menaikkan `BATCH` atau `MAX_REDIRECTS`, hitung ulang. `radio_check::CRON` harus sama dengan salah satu `crons` di `wrangler.toml` (ada tesnya); `scheduled` di `lib.rs` membedakan cron jurnal dan radio lewat ekspresinya. Migrasi `0011` hanya menambah tabel, jadi tetap kompatibel dengan Worker lama. **Dashboard (D7b)**: `GET /admin/radio` dan `POST /admin/radio/check` tidak pernah mengirim URL stream (ada tes di `radio_check.rs` dan `admin-ui.test.mjs`); "Cek sekarang" lewat `radio_check::check_now` (pembatas 60 detik) dan anggaran subrequest-nya dijaga `MANUAL_OVERHEAD`. Tab `web/admin/radio.js` membaca aturan dari respons, jangan menyalin angkanya.
- Kerjakan tahap demi tahap sesuai README repo frontend (D1 → D8) dan centang di sana.
- **Deploy lewat CI (D8a)**: job `deploy` di `ci.yml` jalan hanya pada push tag `v*`, `needs: [migrate]`, `environment: production`. Hanya `CLOUDFLARE_API_TOKEN` dan `CLOUDFLARE_ACCOUNT_ID` yang boleh dipakai job itu; rahasia Worker tidak pernah masuk CI. Jangan memakai `cloudflare/wrangler-action` atau action pihak ketiga lain, jangan memberi `workflow_dispatch` jalan ke deploy, dan jangan memakai `latest` untuk wrangler (`WRANGLER_VERSION` dipin; `worker-build` sama di `ci.yml` dan `wrangler.toml`). Semuanya dijaga `scripts/workflow.test.mjs`.
- **Migrasi production lewat CI**: job `migrate` di `ci.yml` (tag `v*`, `environment: production`) menjalankan `migrate up --yes` lalu `seed --yes`. Jangan menambah `--samples` di sana. Migrasi harus kompatibel mundur dengan Worker yang sedang berjalan (job ini jalan sebelum deploy Worker).
